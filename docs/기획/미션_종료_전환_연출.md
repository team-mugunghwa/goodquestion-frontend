# 미션 종료 → 다음 장면 전환 연출

미션 수행이 끝나고 다음 장면으로 넘어가는 구간의 확정 기획이다.
"미션1 끝나고 전개4로 갈 때가 부자연스럽다"에서 출발했지만, **원인이 전부 값 기반
경로에 있어 미션 없는 대화 종료에도 그대로 적용된다.** 장면 번호로 분기하지 않는다
(`이야기_전개_가이드.md` 3.0절).

관련 문서: `이야기_전개_가이드.md` 3.5·3.6절, `미션_노출_원칙.md`, `DESIGN_SYSTEM.md`
대상 코드: `lib/features/play/presentation/views/play_view.dart`,
`lib/features/play/presentation/widgets/mission_overlay.dart`

## 2. 확정 판단 세 가지

기획안 두 개(흐름/구현 관점, 연출 관점)를 독립으로 받아 교차검증한 결과, **두 안 모두
그대로는 채택 불가**였다. 뒤집힌 지점을 남긴다 — 나중에 같은 제안이 다시 올라올 것이다.

### 2.1 미션 오버레이는 **응답을 받은 뒤에 닫는다** (현행 유지)

두 기획안 모두 "제출 직후 닫고 대화 화면에서 기다리자"였으나 기각한다.

- `이야기_전개_가이드.md` 3.5절이 이미 "**missionId를 실은 발화의 응답을 받으면 닫는다**"로
  정해 두었다.
- 일찍 닫으면 실패 시 되살린 오버레이는 새 인스턴스라 `_answers`가 비어 있다 —
  1장 5번 문제를 그대로 재생산한다.
- 대기 중 X·일시정지가 눌린다. 그 상태에서 응답이 도착하면 `_playCharacterMessage`가
  `_openPauseGate()`를 불러(`:1531`) **멈춘 화면 뒤에서 강제로 소리가 난다.** 재개하면
  `_togglePause` 재개 분기(`:1824-1826`)가 `_playQuestion()`으로 **미션 이전의 낡은 대사를
  다시 읽는다.**

→ 닫는 시점은 그대로 두고, **대기 중 무엇을 보여주는가만 오버레이 안에서 고친다.**

### 2.2 마지막 대사와 결과 이미지의 **순서는 바꾸지 않는다** (지금은)

"결과 이미지를 띄운 위에서 고정 마지막 대사를 재생하면 무음 프레임이 사라지고 새 문구도
필요 없다"는 제안이 있었다. 이득은 분명하지만 지금 구현으로 결정할 일이 아니다.

- `미션_노출_원칙.md`가 "마지막 대사 **이후에** 며느리의 방귀로 배가 떨어지는 결과 연출이
  이어진다"로, `이야기_전개_가이드.md` 3.6절 3번이 "마지막 대사 재생 **뒤** 그 이미지를
  연출로 끼워 넣는다"로 못박고 있다. **기획 문서 2건 개정 + 승인이 필요한 안건**이다.
- 그 대사를 이미지 위 새 패널로 옮기면 **대사 단어 담기(`onWordTap`, `:2130`)가 죽는다.**
  단어장은 담당이 따로 있으므로 사전 조율 없이 건드리지 않는다.
- 반대 방향인 "브리지 문장을 프론트가 창작해 이미지 구간에 얹는다"도 기각한다. 결과
  이미지는 이야기마다 다른데 범용 문구 하나로 커버되지 않는다. 문구를 안 지으면 그것을
  지탱하려던 합성·프리페치·타임아웃 3단 기계도 함께 사라진다.

→ **무음이 죽어 보이는 진짜 원인은 빈 상자·잘린 그림·컷 전환(1장 2·4번)이다.** 렌더링을
먼저 고치고, 실제 에셋으로 눈으로 본 뒤에도 부족하면 그때 재배열을 안건으로 올린다.

### 2.3 대기 화면에 **캐릭터가 아닌 새 애니메이션 장치를 넣지 않는다**

"아이가 말한 생각 수만큼 말풍선 마크 4개를 맥동시키자"는 제안을 기각한다.
`DESIGN_SYSTEM.md`의 "캐릭터가 아닌 곳에서의 과한 애니메이션 — 아이의 주의는 캐릭터에게
가야 합니다"에 정면으로 걸린다. 살아 있음 신호는 캐릭터 thinking 모션과 문구 교체로 낸다.

참고: 이 제안이 근거로 든 `_DialoguePanel`의 "친구가 생각하는 중" 문구는 **죽은 코드**다
(`:2665`에 `// ignore: unused_element`). 살아 있는 어휘는 `_ChildVoiceBubble` 쪽이다.

## 3. 확정 시퀀스

`T+0` = 미션판 제출 탭.

| 구간 | 화면 | 소리 | 왜 |
|---|---|---|---|
| T+0 ~ +0.42 | 미션판 → **오버레이 안의** 대기 화면으로 교체(기존 `AnimatedSwitcher` 420ms). 오버레이는 유지 | 무음 | 보드가 남아 있으면 "버튼이 안 눌렸다"로 읽힌다. 보드를 접는 것 자체가 전송 확인이다 |
| ~ 응답(6~20초) | 캐릭터 thinking + 기존 문구 "이야기 친구가 답을 준비하고 있어요" + **아이의 답 4개를 계속 보여준다**. 7초에 문구 교체, 14초에 한 번 더 | 무음 | 서버가 바쁜 구간에 TTS 요청을 더 얹지 않는다. 문구가 바뀐다는 사실 자체가 "살아 있다"의 신호다. 진행률 바는 쓰지 않는다 — 6초와 20초를 같은 바로 그릴 수 없고, 다 찬 바가 12초 서 있으면 "멈췄다"가 확정된다 |
| 실패 시 | 전체 화면 에러로 가지 않는다. 오버레이 유지 + 보드 복귀 + 인라인 안내 | 무음 | **답 4개가 그대로 살아 있다.** 빨강 없음, "실패" 없음 |
| 응답 도착(R) | 짧은 확인 문구(비평가형) → 오버레이 닫기 | 무음 | 동시에 프리페치 시작: 세션 재조회, 결과 이미지 precache, 다음 장면 배경 precache |
| R ~ R+1.2 | 대화 화면에서 표정 반응(기존 via-홀드) | 무음 | 기존 의도를 처음으로 실제로 보여준다 |
| 이어서 | `closingReaction`(있으면) → `characterMessage` | 캐릭터 목소리 | 3.6절 1번 순서 그대로. **위치·순서 현행 유지**(단어 담기 보존) |
| 대사 끝 +0.3 ~ +0.9 | precache 성공했을 때만: **full-bleed 결과 이미지**로 600ms 크로스페이드(`_SceneBackdrop` 층 + `DialogueBackdropShade` + `_StoryControls` 유지) | 무음 | 어두운 막 위 라운드 박스는 "앱이 띄운 알림"으로 읽힌다. 다른 장면과 같은 층에 그려야 "그 장면 안에 들어왔다"가 된다. 하드코딩 1060×620과 캡션 바는 삭제 |
| +0.9 ~ 약 +3.3 | 이미지 홀드 약 2.4초(재조회가 안 끝났으면 연장, 1.2초 초과 시 기존 문구 "다음 장면을 준비하고 있어요…") | 무음 | 그림은 스피너보다 나은 대기실이고, 어차피 아이가 보고 있어야 하는 것이다 |
| 이어서 | 스피너 없이 크로스페이드로 다음 장면(또는 후속 활동 전환 화면) | 다음 장면 소리 | — |

600ms는 `AppDurations.turn`("차례 전환 … 아이가 알아채야 하는 변화는 일부러 느리게",
`app_motion.dart:26`)이다. 새 숫자를 만들지 않는다.

### 결과 이미지 폴백

```
resultImageUrl 없음            → 대사 끝나고 곧바로 다음 장면
있음 + 제때 디코드             → 크로스페이드 → 홀드 → 다음 장면
있음 + 늦음/실패/CORS 차단     → 없음과 완전히 같은 화면 (건너뛴다)
다음 장면 배경 실패            → DialogueBackdropFallback 으로 크로스페이드 (컷 없음)
```

"그림을 준비하지 못했어요" 같은 안내를 넣지 않는다. 아이가 앱의 사정을 알 이유가 없고,
알면 자기 말이 통하지 않았다고 읽는다. 재시도·다시 보기 버튼도 두지 않는다 — 흘러가는
연출에 조작을 하나 늘리면 초1~3에게는 그것이 과제가 된다.

## 4. 구현 순서

각 단계는 단독으로 커밋·되돌리기 가능하고, 단독으로 가치가 있다.

**1단계 — 미션 오버레이 안의 대기 상태 + 실패 인라인 복구** (비용 대비 효과 1위)
`mission_overlay.dart` 내부 교체와 `_submitMission`의 실패 경로만 손댄다. play_view의
타이밍·전환 로직은 건드리지 않아 회귀 위험이 가장 작다. 이 하나로 **가장 긴 부자연
구간(20초 정지 보드)과 최악의 감정 사고(답 4개 소멸)가 동시에 사라진다.**
- `_activity`(`:267-274`)와 `DialogueCanvas(submitting:)`(`:2103`) 조건에 `_submittingMission`을 더한다
- `_MissionCompleteCard`의 "생각 미션 성공!"(`mission_overlay.dart:1092`)은 3.6절 2번(평가 금지)
  위반이므로 문구를 바꾼다

**2단계 — 결과 이미지 렌더링 수리**
full-bleed 층 + precache 게이트 + 페이드 + 하드코딩 크기 삭제 + 실패 시 통째 생략.
`_ResultSceneOverlay`(`:3795-3841`) 교체. `_StorySceneView`(`:2270-2314`)의 내레이션 카드를
공용 위젯으로 뽑아 쓴다. 골든: 1280×720 / 390×844 / 844×390.

**3단계 — 스피너 제거와 프리페치**
`:1996`의 `if (_loadingSession)`을 `if (_loadingSession && _snapshot == null)`로 좁힌다.
**단 한 줄로는 부족하다** — 조용한 재조회 중 이전 화면이 살아서 마이크가 눌릴 수 있으므로
(에러 재시도 `onRetry: _loadSession`, `:2009` 경로) 재조회 중 입력 잠금을 함께 넣는다.
`_loadSession()`을 `_fetchSession()`(순수 네트워크) + `_applyLoadedSession()`으로 쪼개
네트워크를 마지막 대사가 나오는 동안 미리 돌린다. 현재 전환 1회에 `resume` +
`currentMission` + `sceneMessages` 3회가 순차로 나간다(`:369-377`).

**4단계 — 최상위 크로스페이드**
build가 반환하는 화면을 `AnimatedSwitcher(respect(context, AppDurations.turn))`로 감싼다.
전개1→대화1을 포함한 **모든** 장면 전환이 같은 페이드를 얻는다. 착수 전 확인 필요:
전환 중 두 Scaffold가 함께 살아 `_SceneVideoBackdrop`(`:2358`) 컨트롤러가 둘 초기화되는
웹 비용, 그리고 후속 활동 스냅샷은 `currentScene == null`이라 전환 키 설계에서 recap
오버레이와 이전 대화 캐릭터가 겹칠 수 있다.

**별건 수리** (이 작업과 독립이지만 같은 구간에서 드러난 것)
- 3.5절이 요구하는 **로컬 미션 제출 기록 플래그가 코드에 없다.** 대기 중 새로고침하면
  `currentMission`이 완료된 미션을 계속 돌려주고(`:372-374`), 아이가 재제출하면 턴이 이중으로 나간다
- **일시정지 중 응답 도착 시 강제 해제 버그**(`_playCharacterMessage`의 `_openPauseGate`, `:1531`).
  미션과 무관하게 일반 대화 턴에서도 지금 재현된다

## 5. 착수 전에 사람이 정할 것

1. **대기 문구·확인 문구 신규 카피 승인** (콘텐츠 담당). 기존 어휘를 최대한 재사용하되
   7초/14초 교체 문구는 새로 필요하다
2. **미션 실패 재제출 시 idempotency 키 정책** — 지금은 최종 실패 시 키를 비우므로(`:787`,
   `:792`) 서버가 첫 요청을 이미 처리했다면 턴이 이중으로 나간다. 백엔드에 같은 키
   재수신 동작 확인
3. **대화4(미션2) 종료에 `resultImageUrl`이 실제로 오는지** — 3.6절 3번은 "종료 사유와
   무관하게 장면이 닫히면 항상 온다"인데 8장 에셋 표에는 대화3 것만 있다. 그리고 대화4
   다음은 STORY가 아니라 POST_ACTIVITY라 전환 목적지가 `_RecapHandoffScreen`이다
4. **폰 세로에서 결과 이미지 `cover` / `contain`** — 세로 화면에서 `cover`는 가로 그림의
   좌우를 크게 잘라 "우수수"를 지운다. 실제 에셋 없이는 정할 수 없다
5. **2단계 완료 후 무음 구간 재평가** — 부족하면 2.2의 순서 재배열을 안건으로 올린다.
   개정 대상은 `이야기_전개_가이드.md` 3.6절 3번과 `미션_노출_원칙.md`, 승인은 기획·콘텐츠
   담당, 단어 담기 영향은 단어장 담당과 합의
