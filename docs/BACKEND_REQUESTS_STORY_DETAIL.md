## 0. 먼저 — 왜 시드 문제인가

기획(`docs/기획/MVP_요건.md`, "이야기 선택" 행)의 요건은 한 줄이다.

> 상세 화면에 **이야기 도입, 상황, 아이 역할** 표시

이것이 `docs/데이터베이스_설계.md` §3.1 에서 이렇게 매핑돼 있다.

| 기획 항목 | 컬럼 | 설계 문서 설명 |
|---|---|---|
| 도입 + 상황 | `stories.intro` | "상세 화면 도입/상황 소개" — **두 항목이 한 필드** |
| 아이 역할 | `stories.child_role` | "상세 화면 아이 역할" |
| (소개) | `stories.summary` | "이야기 목록·상세 화면에 표시할 소개" |

`StoryDetailResponse{story, sceneCount, childRole, intro}` 와 `StoryCardResponse` 가
이 셋을 모두 내려주고 있으므로 **서버 구현은 기획을 정확히 만족한다.** 비어 보이는 건
`stories` 행의 `child_role`·`intro` 가 `null` 이기 때문이다.

> 프런트에 있던 `role.description`(역할 설명)·`situationText`(별도 상황문)·`introAudio` 는
> 더미 화면을 만들 때 프런트가 임의로 넣은 필드였다. 기획·서버 어디에도 없어
> **프런트에서 걷어냈다.** 서버에 추가 요청하지 않는다.

### 실서버 현황 (2026-08-16, Railway)

| 이야기 | 장면 | `childRole` | `intro` |
|---|---|---|---|
| 작은 씨앗 | 3 | `씨앗을 돌보는 아이` | ✅ |
| 방귀 뀌는 며느리 | 9 | `null` | `null` |
| 나머지 6편 | 0 | `null` | `null` |

**방귀 뀌는 며느리가 문제의 핵심이다.** 장면 9개가 다 들어간 MVP 메인 콘텐츠인데
상세 화면만 비어 있다. `R__1_seed_content.sql` 의 `stories` insert 가 컬럼 목록에서
`child_role`·`intro` 를 빠뜨렸고(`R__2` 의 작은 씨앗은 넣고 있다), 그 뒤로 아무도
안 채웠다.

## 1. 방귀 뀌는 며느리 — `child_role`·`intro` 추가

**대상**: `src/main/resources/db/migration/R__1_seed_content.sql`, `stories` insert
(`11111111-1111-1111-1111-111111111111`)

### 제안 값

| 컬럼 | 값 |
|---|---|
| `child_role` | `마을 사람들의 고민을 들어주는 아이` |
| `intro` | `옛날 어느 마을에, 방귀를 아주 크게 뀌는 며느리가 살았어요.`<br>`이상하게 볼까 봐 걱정이 되어서, 며느리는 방귀를 꾹꾹 참고 있어요.` |

**`intro` 근거**: 콘텐츠 문서 `docs/기획/이야기_방귀_뀌는_며느리.md` 1절 "도입" 단락을
아이 눈높이 두 문장으로 줄였다. 형식은 `R__2` 의 작은 씨앗을 그대로 따랐다 —
**앞 문장이 도입(누가), 뒤 문장이 상황(지금 무슨 일)** 이다.

```
작은 씨앗: '마당 한구석에 씨앗을 심었어요. 그런데 아무리 기다려도 싹이 나지 않아요.'
```

**`child_role` 근거 — 콘텐츠팀 확정이 필요하다.** 콘텐츠 문서에 아이 역할을 명시한
곳이 없어 대화 4장면의 구조에서 역산했다. 아이는 며느리(대화1·4)·시아버지(대화2)·
마을 이장(대화3) **세 사람 모두와** 이야기하고, 캐릭터 `guidance_style` 이 하나같이
"아이가 먼저 말하고 싶게", "아이가 까닭을 더 설명하게", "아이가 방법을 더 구체적으로
말하게" 로 적혀 있다. 즉 아이는 **한 인물의 편이 아니라 마을 사람들의 고민을 듣고
방법을 같이 찾는 상대**다.

- 대안 1: `며느리네 마을에 놀러 온 친구` — 아이 화면 문구가 더 부드럽다
- 대안 2: `마을 사람들의 이야기를 듣는 친구`
- ❌ `며느리의 친구` — 프런트 더미에 있던 값. 시아버지·이장과의 대화를 설명하지 못해 제외했다

화면에는 `이 이야기에서 너는 "○○"야!` 형태로 나온다. 길이가 문구 인상을 좌우하니
콘텐츠팀 감각으로 골라 주면 좋겠다. (`varchar(50)` 제한)

### 변경 SQL

두 군데를 고쳐야 한다. **`on conflict do update set` 목록을 같이 고치지 않으면
이미 행이 있는 환경(Railway)에는 반영되지 않는다.**

```sql
-- (1) 컬럼 목록과 VALUES
insert into stories (id, title, summary, child_role, intro, image_url, difficulty,
                     estimated_minutes, post_activity_config, status) values
(
    '11111111-1111-1111-1111-111111111111',
    '방귀 뀌는 며느리',
    '큰 방귀를 부끄러워하던 며느리가 자신의 다름을 장점으로 바꾸는 이야기',
    '마을 사람들의 고민을 들어주는 아이',
    '옛날 어느 마을에, 방귀를 아주 크게 뀌는 며느리가 살았어요. 이상하게 볼까 봐 걱정이 되어서, 며느리는 방귀를 꾹꾹 참고 있어요.',
    '/stories/banggui/cover.jpg',
    ...
)

-- (2) 업서트 갱신 목록 — 이 두 줄이 빠지면 기존 배포 DB는 그대로 null 이다
on conflict (id) do update set
    title = excluded.title,
    summary = excluded.summary,
    child_role = excluded.child_role,   -- 추가
    intro = excluded.intro,             -- 추가
    image_url = excluded.image_url,
    ...
```

Repeatable 마이그레이션이라 파일 체크섬이 바뀌면 재기동 시 자동 반영된다.

## 2. 장면 없는 6편 — 상세는 채우고, 노출 여부는 남겨 둠

**대상**: `R__3_seed_story_cards.sql` (해와 달이 된 오누이, 의좋은 형제, 흥부와 놀부,
호랑이와 곶감, 토끼와 거북이, 학교 가는 길)

이 6편도 `child_role`·`intro` 를 채웠다(#79). 표지를 보고 들어온 아이가 아무 안내
없이 되돌아 나가는 것보다는 낫다는 판단이다. 원문 대본이 없어 널리 알려진 줄거리에서
두 문장으로 뽑았고, **장면 대본이 준비되면 대본의 도입 장면에 맞춰 다시 손보는 것을
전제**로 한다.

다만 이 6편은 여전히 `sceneCount` 가 0이라 **세션 시작이 404** 다.

```
POST /children/{id}/sessions → 404 {"code":"NOT_FOUND","message":"장면이 없습니다."}
```

프런트는 이 실패를 에러 화면으로 받는다(눌러도 안 되는 "다시 불러오기"가 뜬다).
장면 대본이 없으니 당연한 동작이라 이번 범위에서는 손대지 않았다. 목록에서 감출지
(`status='DRAFT'`)는 `R__3` 주석이 남겨 둔 대로 **콘텐츠팀 판단으로 남긴다** —
감추면 목록이 2편으로 줄어든다.

## 부록 — 프런트에서 함께 정리한 것

서버 변경과 무관하게, 상세 화면을 위 계약에 맞춰 정리했다.

| 항목 | 처리 |
|---|---|
| `StoryRole.description` | 제거 (기획·서버에 없는 필드) |
| `situationText` | `summary` 로 정정 — 서버 `story.summary` 를 상황문인 척 쓰고 있었다 |
| 빈 `childRole`·`intro` | 해당 영역을 렌더하지 않음 (빈 카드 방지) |
| `introAudio` | 서버 미제공이라 "들려줘" 버튼을 숨김(영구 비활성 버튼 방지). TTS(501) 가 붙으면 그대로 살아남 |
