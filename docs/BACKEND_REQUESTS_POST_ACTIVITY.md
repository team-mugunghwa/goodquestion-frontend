# 백엔드 요청 — 말하기 후 활동 카드 이미지 (2026-08-15)

대상 저장소: `team-mugunghwa/goodquestion-backend` (`develop`)
요청 배경: 말하기 후 활동(순서 맞추기 → 다시 말하기) 화면을 구현하면서 [API.md](API.md) 2.10 의
DTO 계약과 확정된 활동 방식을 대조했다. 카드가 **텍스트 전제**로 설계돼 있어 그림 카드로는
화면을 그릴 수 없다.

기획 확정안: 주요 장면 카드 4~5개를 무작위 제시 → 아이가 이야기 순서대로 배열 →
정답이면 핵심 단어 3~4개 제공 → 카드와 단어를 참고해 전체 이야기를 음성으로 재구성

## 1. `Card` 에 `imageUrl` 추가

**대상**: `PostActivityStartResponse.Card` (`PostActivityStatusResponse` 가 재사용)

### 현재

```
Card: cardId · text
```

### 요청

```
Card: cardId · text · imageUrl
```

**활동이 "그림만 보고 순서 맞추기"로 확정됐다.** 카드에 장면 제목을 띄우면 정답이 그대로
새어 나가므로 화면에는 그림만 그린다. `text` 만으로는 카드를 그릴 수 없다.

`imageUrl` 은 다른 이미지 필드(`storyImage` · `coverImage` · `SceneContentResponse.imageUrl`)와
똑같이 **서버 정적 서빙 경로**(`/stories/**`)로 내려주면 된다.

> 대화 장면 캐릭터 에셋은 프런트 번들로 갔지만([BACKEND_REQUESTS.md](BACKEND_REQUESTS.md) 부록)
> 카드는 서버 URL 로 간다. 캐릭터는 상태 머신이 골라 쓰는 **런타임 에셋**이라 번들이 맞았고,
> 카드는 이야기가 늘어날 때마다 늘어나는 **콘텐츠**라 앱 배포 없이 추가돼야 하기 때문이다.

### `text` 는 남겨 달라

화면에 그리지는 않지만 **스크린리더 라벨로 쓴다.** 그림만 있는 카드는 라벨이 없으면
활동 자체가 불가능하다. 아래 시드 표의 문장 정도면 충분하다.

## 2. 시드 — 방귀 뀌는 며느리 (`story_11`)

### 카드 4장 — 아래가 정답 순서

| 순서 | 장면 | `text` (스크린리더 라벨) |
|---|---|---|
| 1 | 며느리가 방귀를 참아 얼굴이 노래짐 | 며느리가 방귀를 참느라 시무룩하게 서 있어요 |
| 2 | 시아버지의 갓이 날아가고 며느리가 쫓겨남 | 며느리의 방귀에 시아버지의 갓이 날아가 시아버지가 화를 냈어요 |
| 3 | 방귀로 배나무의 배를 떨어뜨림 | 며느리가 방귀로 배나무의 배를 우수수 떨어뜨렸어요 |
| 4 | 마을 사람들이 배를 얻고 고마워함 | 마을 사람들이 배를 얻고 며느리에게 고마워했어요 |

### 핵심 단어 4개 (`retellingKeywords`)

`참다` · `쫓겨나다` · `떨어뜨리다` · `자신감`

네 장면과 1:1로 대응한다. 화면에는 순서대로 칩으로 나란히 보여 주고, 장면과 짝지어
그리지는 않는다.

### 이미지 원본 전달

프런트가 갖고 있다 — 1920x1080 PNG 4장. **전달 방식을 알려 달라** (백엔드 저장소 커밋 /
스토리지 직접 업로드 / 파일 전달 중 무엇인지).

---

## 3. 전제 — 카드 개수는 고정이 아니다

**이야기마다 카드 개수가 다르다.** 기획 원문의 "4~5개"는 예시 범위이지 상한이 아니다.

그래서 프런트는 개수를 고정하지 않고 **응답 길이대로 슬롯을 그린다** — 5장이 오면 슬롯도
5칸이 된다. 백엔드도 카드 개수에 대한 검증을 4로 박지 말아 달라.

방귀 뀌는 며느리가 4장인 것은 이 이야기의 값일 뿐이다. 아래 시드를 보고 "카드는 4장"으로
읽지 않도록 주의.

## 부록. 서버가 열릴 때까지의 프런트 구현

2.10 의 네 엔드포인트가 모두 501 이라, 그동안 프런트는 화면 코드에 하드코딩한다.

| 지금 | 서버가 열리면 |
|---|---|
| 카드 4장이 화면 코드에 상수로 박혀 있음 | `POST /post-activity/start` 응답 |
| 정답 순서를 프런트가 알고 로컬 판정 | `POST /post-activity/order` — **판정은 서버만 한다** |
| 키워드 4개가 상수 | `CardSubmitResponse.retellingKeywords` |
| 발화 텍스트가 데모 문자열 | `POST /post-activity/retelling` |

**화면 구조는 바뀌지 않는다.** 위 네 줄만 갈아 끼우면 된다.

로컬 폴백 에셋: `assets/images/recap/banggui/scene_{1,2,3,4}.webp` (960x540 WebP, 총 400KB).
`imageUrl` 이 오기 시작하면 이 에셋은 네트워크 실패 시 폴백으로만 남긴다.
